See it

Try it

Move your pointer down the arrows and read each step in the pane below. Then click the empty background of the diagram to open it full screen.

Columns, arrows, and loops

Each participant gets a column with a line running down from its name. Each message is an arrow from the sender’s line to the receiver’s line, so reading down the page follows time. An arrow that leaves and returns to the same line is a loop: the participant doing work on its own, such as checking a payment.

The selected message is marked and its detail appears below the diagram. A wide diagram scrolls sideways inside its own frame rather than widening the page.

Read messages from a data source

A diagram can also read its messages from a named data source. This one lists a declined payment. It shares message keys with the checkout above through linked selection, so choosing a step in either diagram marks the same step in the other.

Same start. The order is placed exactly as before.

Same check. The payment service runs its usual checks.

Different answer. This time the payment service declines.

Try it

Select Decline in the second diagram and watch the first diagram move to Approve, the matching step. The detail pane for the second diagram sits outside its figure and still follows it.

When to reach for it

Use a sequence diagram when the order of messages matters more than the structure of the system. Keep to a handful of participants; if the arrows start to cross the whole page, split the story into two diagrams. For a process without senders and receivers, a pipeline diagram is usually clearer.

For every reader

Tab reaches the selected message. ↑ and ↓ move through messages, and Home and End jump to the first and last. Each message button names its sender, receiver, and step number for screen readers. In the enlarged view, the cursor, magnifier, laser, pen, highlighter, and eraser are available; there is no ruler. With scripts off, or in print, the authored list of messages and every detail stay readable.
