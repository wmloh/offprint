Points, spans, and lanes

An event with only a start is a dot. An event with a later end is a bar that runs from start to end. Lanes appear in the order they are first used, and events in a lane are sorted by start. When two events in a lane overlap, the later one moves to a new row so neither label is hidden. The diagram can begin on any event; this one opens on the review.

The axis can use calendar dates, as above, or plain numbers such as days, seconds, or steps. Put the unit in the caption so readers know what the numbers mean.

Read events from a data source

This diagram reads a CSV data source that counts days from kickoff. It shares event keys with the calendar above through linked selection, so selecting an event in either view updates both.

Try it

Select Publish in the lower diagram and watch the calendar move to the same event. Then click the background of either diagram to enlarge it, choose the measure tool with 6, and point at the axis to read a date or day and its lane.

When to reach for it

Use a timeline when when and how long matter, especially when work runs in parallel. For a strict order of steps without durations, a worked-example stepper or pipeline diagram is lighter. Keep labels short; the full label is always in the event’s hint and detail.

For every reader

Tab reaches the selected event. ← and → move to the previous or next event in lane order, and Home and End jump to the ends. On a phone, the axis scrolls sideways inside the figure. Print shows a list of the events with their dates or numbers, and with scripts off the authored list and every detail stay readable.
