Reference

Offline tools

OffPrint includes a tool that prepares a site's search index and data files without the internet. This page explains what it checks and when to run it again.

Use it to
Keep search and data files up to date
Reading time
About 5 minutes

What the asset tool does

Open the offline asset tool, a page for checking and rebuilding your prepared files. Choose the folder containing your site. The tool reads the site settings, finds the pages and data they name, and compares each prepared file with the version it would make from those inputs today.

Current
The prepared file matches the current inputs.
Missing
The prepared file has yet to be saved where the site expects it.
Stale
The saved file is out of date and can be rebuilt.
Blocked
The tool needs a correction first, such as restoring a missing source file.

Choose the files to regenerate. Where the browser offers save access, the tool can save them into the site folder. Otherwise it downloads them and shows where each belongs. The files stay on your device.

The search index

The search index collects written page text, headings, term uses, and definitions attached to words on individual pages. Search reads the index to find matches on other pages. Navigation and link previews use it too, and the glossary uses it to show where terms were used.

Search can still read the current page directly. This explains why a new heading may appear in search while you are on that page and be missing when you search from another page.

Offline data files

The Data file wrapper packages a CSV, JSON, or YAML source so a local page can read it. The tool checks that the source can be read and prepares it under the site's chosen name. The site can then use it in charts, tables, and other views.

A reader can still open a file temporarily with File dropzones. That choice affects the current page. The prepared file stays as it was.

Refresh from the terminal

The Terminal asset refresh script does the asset tool's job without opening a browser. From the OffPrint checkout, run it with Python 3.9 or later. It rebuilds every prepared file that is out of date, both the search index and the data file wrappers, and leaves current files untouched. Then reload the open page.

python3 docs/refresh-assets.py

Add --check to only report each file as Current, Missing, Stale, or Blocked, without changing anything. If anything is blocked, nothing is written until it is fixed.

  • The search index needs Node.js. Without it, the script still refreshes data and reports the index as skipped, so use the asset tool for the index.
  • YAML data files also need the PyYAML package.
  • The script reads pages more strictly than a browser. If it reports a page and line, fix the markup there, such as a tag left open or a & that should be written &amp;.

For your own site, copy the project launcher next to your pages. Adjust the paths to OffPrint's tools/refresh_assets.py and your site.js.

When to run it again

  • Ask for the search index to be checked after writing, renaming, moving, adding, or removing pages. Check it after changing headings, definitions, or the list of pages included in search.
  • Ask for the data file wrappers to be checked after updating a source file or changing which source a page loads.
  • Before handing the site to someone else, ask for a check of all prepared files. Files marked Missing or Stale are ready to rebuild. Files marked Blocked need the cause fixed first.
