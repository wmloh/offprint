Computing with matrices

The ideas so far run on paper, but most real matrices are too big for that. This page shows how a matrix-vector product looks in code, how fast the common approaches are, and how the standard solvers compare. Timings are illustrative, not measured on your machine.

A matrix-vector product by hand

Each entry of A\vec x is the dot product of one row of A with \vec x. The loop below spells that out; the highlighted lines do the work. Hover a numbered marker to read its note. 


      import numpy as np

      def matvec(A, x):
          n, m = A.shape  # (1)
          y = np.zeros(n)
          for i in range(n):
              y[i] = A[i] @ x  # (2)
          return y

      A = np.array([[2.0, -1.0], [1.0, 1.0]])
      print(matvec(A, np.array([2.0, 1.0])))  # (3)
  1. An n \times m matrix needs \vec x \in \R^m; the result lives in \R^n.
  2. Row i dotted with \vec x gives entry y_i.
  3. Prints [3. 3.], the same A\vec x = (3, 3) as the column picture on the matrices page.

Letting the library do it

NumPy already has the product built in. The diff shows what changes when the loop goes away:

        def matvec(A, x):
            n, m = A.shape
            y = np.zeros(n)
            for i in range(n):
                y[i] = A[i] @ x
            return y
      
        def matvec(A, x):
            return A @ x

A diff can also be written by hand with + and - at the start of each line:


      @@ solve.py @@
      -x = np.linalg.inv(A) @ b
      +x = np.linalg.solve(A, b)
       print(np.allclose(A @ x, b))

When answers go wrong
