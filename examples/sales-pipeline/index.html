When a sale arrives twice

A checkout sends a $12 sale to a reporting service. Follow the timeout and retry, then trace the sales total to its source rows.

Follow the retry on two clocks

The receiver started 20 seconds before the first send. Sender time 0 s and receiver time 20 s describe the same instant. Each message carries the sale ID S41. The steps, the event rows, and the points on the chart share one key per event: moving through the steps outlines the matching row and point, and selecting a point opens its step.

  1. Send the sale. Checkout sends S41 for $12 and waits up to two seconds for confirmation. The message is delayed in transit, so the receiver has yet to record a sale.
  2. Retry after the timeout. Checkout resends the same ID. The retry takes a faster path and arrives first. The receiver records S41 once, adding $12.
  3. Handle the delayed original. The original send arrives after the retry. Its sale ID is already in the report, so the receiver skips this arrival and the total stays $12.

Count each sale once

The report stores every arrival and keeps the earliest row for each sale ID. The same rule can run in the database or in the receiving service.


CREATE TABLE arrivals (
  sale_id     VARCHAR(8)    NOT NULL,
  amount      NUMERIC(10,2) NOT NULL,
  received_at NUMERIC(6,1)  NOT NULL  -- (1)
);

SELECT SUM(amount) AS total
FROM (
  SELECT amount,
         ROW_NUMBER() OVER (PARTITION BY sale_id
                            ORDER BY received_at) AS arrival  -- (2)
  FROM arrivals
) ranked
WHERE arrival = 1;
  1. Seconds on the receiver clock, such as 22.3 and 23.2.
  2. The earliest arrival of each sale ID gets number 1, so a repeated ID counts once.

public sealed class SalesTotal
{
    private readonly HashSet<string> seen = new();

    public decimal Total { get; private set; }

    public void Receive(string saleId, decimal amount)
    {
        if (!seen.Add(saleId)) return;  // (1)
        Total += amount;
    }
}
  1. Add returns false for an ID that is already counted, so the late original adds $0.

Summing every row would count the repeated ID twice. The fix sums the ranked rows instead, keeping only the first arrival:

SELECT SUM(amount) AS total  -- $24 for the repeated ID
FROM arrivals;
SELECT SUM(amount) AS total  -- $12 for the repeated ID
FROM ranked
WHERE arrival = 1;

Place batches on one clock

The store sends its sales in batches through the evening, stamping each batch with its own clock, five hours behind UTC. Batches arrive at uneven intervals, and the 19:05 batch failed to upload, so its row has no count. The daily report closes at midnight UTC, which is 19:00 on the store clock. Sales in later batches count toward the next day's report.
