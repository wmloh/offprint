Follow two validation metrics through training

Use Next to advance both charts by training step. Focus either plot and use the arrow keys to inspect a recorded point and see its step on the other chart. The loss bands show supplied synthetic 95% intervals over 20 validation examples. Each metric has its own sampling schedule.

  1. Step 0 · Before training Both runs start near 1.8 nats and match one in five validation tokens.
  2. Step 400 · Candidate schedule changes The candidate begins decaying its learning rate here. Neither metric was sampled at this step.
  3. Step 1000 · Final checkpoint The candidate finishes at 0.57 nats and 95% accuracy, compared with the baseline's 0.72 nats and 85%.

Check file limits and parse errors

This configuration preview has a 256-byte limit. Select Show anyway to display the YAML as code.

{
  "run": "r04",
  "validation_loss": 0.57
}

The comma after "r04" separates the two JSON properties. Omitting it causes a parse error on the next line.

Package results for offline viewing

To swap the built-in run log, keep its column names, edit runs.csv, and regenerate generated/runs.js with the offline asset tool. The site manifest loads the generated script. The shell command checks the first few lines, and the HTML shows the markup for a data view with a narrower width limit.

head -n 5 runs.csv
<div class="run-log" data-df-source="runs" data-df-data-view="table" data-df-max-width="960px"></div>
