# Base layout and typography

Enable `base` (included in the reading profile and `offprint.css`). Use `<main class="op-page">` as a direct child of `body`. An optional sibling `<nav class="op-sidebar">` enables the desktop sidebar grid. Author headings, paragraphs, figures, and tables in reading order.

- Desktop with a hover-capable pointer and viewport wider than 860 px. The reading column caps at `--op-content-width` (1120 px) plus two `--op-page-gutter` values (24 px each). It centers in the viewport when the sidebar clears it and shifts beside the sidebar otherwise. It sizes against the configured sidebar width in either visibility state.
- At 860 px and below, or with no hover-capable pointer, the base layout stacks and uses 16 px inner gutters. [Navigation](navigation.md) enhances the sidebar into a drawer. The design viewport is 1920 × 1080.
- Default typography is 16 px system sans-serif at line height 1.6. `h1`, `h2`, and `h3` use 1.875, 1.5, and 1.25 em. A first-child `h1` directly under `.op-page` uses 2.5 em. `h4`–`h6` use 1 em. Direct `.op-page` children (not bubble bodies): `h2` top margin `--op-space-h2` (56 px), `h3` `--op-space-h3` (32 px); 0 as first child; 0.5 em after another heading. [Section lines](sections.md) style these `h2`s. Code uses the mono token. Underlined links use `--op-link`.
- Standalone figures, tables, media, and captions center where applicable. Tables and code blocks scroll horizontally inside the reading column.
- Width limits: outermost figures, tables, `pre`, `.op-code`, `[data-op-chart]`, `.op-figure`, `.op-anim`, `.op-tabs`/`[data-op-tabs]`, `.op-split`, `.op-data`, `[data-op-data-view]`, and `.op-tree` get `max-width: min(100%, --op-figure-max-width)` (default `100%`) and center. Nested blocks of these kinds keep 100 % of their container, so percentage limits do not compound. `data-op-max-width` on any element in `.op-page` sets that element's own limit (positive length or percentage, e.g. `720px`, `42rem`, `80%`), still capped at 100 %. `core.js` validates it into inline `--op-max-width` at startup and on attribute changes; invalid values report a `base` diagnostic and fall back to 100 %. Browsers with typed `attr()` also read it without script. Contents scale (images, SVG, video, canvas, iframes, charts redraw at the new plot width) or scroll (tables, code). Nothing in `.op-page` grows past the column; zoomed figures leave `.op-page` and use the zoom view's width. Table hover tints the row and, for the first 12 cell positions, the column, headers included.
- Lists use accented counter badges and dots with hover feedback. The tint follows `data-op-color` or `data-op-role` on an item, list, or ancestor, with gray as the default. Put `data-op-no-list-style` on a list or ancestor for native markers. Navigation lists, lists with an explicit `role`, and the roles legend also skip custom markers. List margin, padding, marker type, and marker colour defaults have zero specificity, so any module class rule overrides them; custom markers do not, so script-built non-prose lists (chips, menus) need `role` or `data-op-no-list-style`.
- Sidebar, table, and `pre` scrollbars use a transparent thumb until hover or visible focus. The page scrollbar is handled by [reading controls](controls.md).
